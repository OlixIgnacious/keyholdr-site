    02

    Hardware-backed.
    Nothing in cleartext.

    Metadata and secrets never travel together. Names and labels live in a local file — the secrets themselves go straight into the operating system's hardware-backed vault and never touch the disk in cleartext.

    • 2.1

      System vaults only

      Secrets are written straight to your Mac's hardware-backed credential store, Keychain Services, encrypted by macOS.

    • 2.2

      Biometric gate

      Touch ID or Apple Watch is required before any secret is decrypted. Physical presence, every time.

    • 2.3

      Strictly local

      No servers, no sync, no analytics, no network calls. Your keys never leave the machine.

    • 2.4

      Self-healing

      The key list mirrors itself into the OS vault. Delete the app, its files, or both — reinstall and everything is still there.

    • 2.5

      Privacy nutrition label

      Keyholdr declares no data collected on the Mac App Store. No identifiers, no usage data, no diagnostics — nothing leaves your device.

    • 2.6

      Notes aren't secrets

      Scratch notes are plain text in a local file — not in the Keychain and not behind Touch ID. Keep API keys in Keys, and use Notes for everything else.

    Questions,
    answered.

    What is Keyholdr?

    Keyholdr is a free, native macOS app for storing API keys. It lives in the menu bar, keeps each secret as its own item in the macOS Keychain, and asks for Touch ID before any key is copied or read. A keyholdr command-line tool and full-screen terminal UI use the same vault. It runs on macOS 13 Ventura or later and is under 1 MB.

    Where should I store API keys on a Mac?

    In the macOS Keychain, not in ~/.zshrc, a .env file or a notes app. The Keychain encrypts items on disk and can require Touch ID before releasing one. Then pass a key only to the command that needs it, for example keyholdr run -e OPENAI_API_KEY=openai -- npm start. The full guide covers each option.

    How is Keyholdr different from a .env file?

    A .env file is plain text that any program running as you can read, and it is easy to commit, copy into a Docker image or sync by accident. With Keyholdr the secret stays encrypted in the Keychain and is handed only to the command you run, after Touch ID. If a tool insists on a .env file, keyholdr env --dotenv prints one on demand.

    Does Keyholdr ask for Touch ID every time?

    Yes. Every copy, every reveal and every terminal read asks for Touch ID. Macs without Touch ID use Apple Watch or your login password instead. The popover locks again as soon as you click away.

    Does Keyholdr sync my keys to iCloud?

    No. Keyholdr makes no network connections, and keys are never sent to iCloud or any server. To move to a new Mac, export the vault to one passphrase-encrypted file (PBKDF2-SHA256, then AES-256-GCM) and import it there.

    Can I use my keys from the terminal?

    Yes. keyholdr run injects keys into one command as environment variables, keyholdr env loads them into the current shell, keyholdr get prints one, and bare keyholdr opens a full-screen terminal UI. The Mac App Store version is sandboxed, so for the terminal install the Homebrew build: brew install --cask olixignacious/tap/keyholdr. See the CLI reference.

    Can AI coding assistants use my keys?

    Yes, through a small MCP bridge that calls the keyholdr command for Claude Desktop, Claude Code and other MCP clients. Every request still shows a Touch ID prompt on your Mac, and nothing gets pasted into a config file or a chat.

    How does Keyholdr compare with other API key managers?

    Keyholdr is free, works in both the menu bar and the terminal, asks for Touch ID on every read and runs on macOS 13. It doesn't sync between Macs, import .env files or clear the clipboard. The comparison with NoxKey, Fidelius, EnvVault, 1Password CLI and others covers which one fits which workflow.

    Is Keyholdr free? Is it open source?

    Keyholdr is free, with no account. Its source code is public on GitHub under a non-commercial licence: you can read, build and modify it for personal use, but it is not an OSI open-source licence.
